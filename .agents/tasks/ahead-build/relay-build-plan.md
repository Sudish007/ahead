## Decisions (settled; implementers do not re-open them)

- **D1 Allowlist source of truth = `sources.config.mjs` via two new optional fields.** `viaRelay: true` on the six sources; `relayPagePrefix: 'https://www.deeplearning.ai/the-batch/'` on `thebatch`. `relay/build-allowlist.mjs` exports `buildAllowlist(sources)` and, when run as a script, writes `relay/src/allowlist.json` (committed, regenerated by hand after config changes; a test fails when it is stale). Shape, keys sorted by id, 2-space JSON, LF, trailing newline:
  ```json
  {
    "note": "generated by relay/build-allowlist.mjs from sources.config.mjs and src/http.js; do not edit by hand",
    "feeds": { "chinai": "https://chinai.substack.com/feed", "epoch-gradient-updates": "https://epochai.substack.com/feed", "importai": "https://importai.substack.com/feed", "pod-dwarkesh": "https://api.substack.com/feed/podcast/69345.rss", "thebatch": "https://www.deeplearning.ai/sitemap.xml", "zvi": "https://thezvi.substack.com/feed" },
    "pages": { "thebatch": "https://www.deeplearning.ai/the-batch/" },
    "headers": { "user-agent": "<BROWSER_USER_AGENT>", "accept-language": "<ACCEPT_LANGUAGE>", "accept-feed": "<ACCEPT.feed>", "accept-html": "<ACCEPT.html>" }
  }
  ```
  The `headers` block is imported from `src/http.js` so the Worker sends exactly the pipeline's browser-like headers (the probe showed headers do not decide the outcome; this just avoids drift). Schema rules: `viaRelay` must be boolean, allowed only on `type` rss|atom|sitemap and never with `template: true`; `relayPagePrefix` allowed only on `type: 'sitemap'`, must be an `https:` URL with no credentials/query/hash that ends with `/`, and is required when a sitemap source has `viaRelay: true`.
- **D2 Worker `ahead-relay`, plain JS module Worker, wrangler as the only (dev) dependency, in `relay/` only.** `relay/package.json` (`private`, `type: module`, `devDependencies.wrangler = "4.151.2"` exact pin, scripts `allowlist`, `deploy`, `tail`), `relay/package-lock.json` committed, `relay/node_modules` ignored by the root `.gitignore` (`node_modules`, unanchored). Root `package.json` unchanged. Wrangler's built-in esbuild bundling is used (that is not "a bundler" in the task's sense); `relay/src/index.js` imports the allowlist with `import allowlist from './allowlist.json' with { type: 'json' };` so the same file loads in Node 24 tests and in wrangler.
- **D3 Routes and auth (not an open proxy).** Auth runs first: header `x-relay-token` (trimmed) must equal `env.RELAY_TOKEN` (trimmed) via a constant-time compare, else `401 {"error":"unauthorized"}`; a Worker without the secret answers 401 to everything. Then: `GET /feed/<id>` with `id` in `allowlist.feeds` -> serve that URL with the feed Accept; `GET /page/<id>?u=<url>` with `id` in `allowlist.pages`, `u` parseable by `new URL`, and `new URL(u).href.startsWith(allowlist.pages[id])` -> serve the normalized `href` with `text/html` Accept; anything else (other paths, trailing slashes, non-GET, unknown id, missing or disallowed `u`, `http:` or credentials in `u`) -> `404 {"error":"not found"}`. The token is never forwarded upstream and never echoed in any response.
- **D4 Last-good copy in KV (`RELAY_CACHE`).** Key `v1:<upstream url>`; value = raw body bytes (ArrayBuffer); metadata `{ contentType, fetchedAt }` (content-type cut to 100 chars; `fetchedAt` ISO); `expirationTtl` 30 days so a URL that leaves the registry eventually disappears. Read path per request: `getWithMetadata(key, { type: 'arrayBuffer' })`; copy younger than `FRESH_MS = 2 h` -> serve it (`x-relay-cache: hit`); otherwise fetch upstream; on success store (`ctx.waitUntil(put)`) and serve (`x-relay-cache: miss`); on upstream failure with a copy -> serve the copy with `x-relay-cache: stale` and `x-relay-stale: <fetchedAt>`; on failure with no copy -> `502` JSON `{ "error": "upstream failed", "url", "upstreamStatus": <int|null>, "cfMitigated": <string|null>, "reason": "status"|"timeout"|"network" }`. Every response carries `cache-control: no-store`; 200s pass the upstream `content-type` through (fallback `application/octet-stream`) and nothing else from upstream (no content-encoding/length: Workers decode bodies). Rationale for raw-bytes value + metadata instead of one JSON blob: the three fields are still stored per URL key, and reads/writes do no JSON work on a multi-MB body, which keeps CPU far under the free plan's 10 ms.
- **D5 Store cap 4,000,000 bytes, not 2 MB (deviation, flagged).** `thezvi.substack.com/feed` measured 2,027,091 bytes on 2026-10-20, so a 2 MB cap would exclude the largest of the six feeds from the last-good copy and from the cron refresh (it would be fetched upstream on every pipeline run, with no stale fallback). `MAX_STORE_BYTES = 4_000_000` keeps headroom; bodies over the cap are still served pass-through (`x-relay-cache: bypass`) and never stored. Footprint: 6 copies x <= 4 MB plus <= 30 article pages x ~170 KB, far below 1 GB; KV values may be 25 MiB.
- **D6 Upstream fetch policy (from the probe's 429 analysis).** `fetch(url, { headers: allowlist.headers (+accept by kind), redirect: 'follow', signal: AbortSignal.timeout(10_000) })`. Failure = status !== 200 OR any `cf-mitigated` header. One retry after 2 s on 429 only (the probe saw a 429 clear 2 s later; 5xx/timeouts go straight to stale-or-502 so the Worker answers within the pipeline's 15 s relay timeout). One JSON log line per upstream attempt: `{ "event": "upstream", "path": "request"|"cron", "url", "status", "cfRay", "cfCacheStatus", "cfMitigated", "bytes", "ms", "attempt" }` (visible in `npx wrangler tail ahead-relay` and Workers Logs; `[observability] enabled = true`), which is how a colo-dependent challenge or a 429 pattern would show up in the first days.
- **D7 Cron `0 */3 * * *` refreshes every `allowlist.feeds` URL (the five Substack feeds and the sitemap; not pages) sequentially in id order with a 2 s gap** (probe caveat: never fan Substack out in parallel; all five feeds share the egress IP's budget). A failed refresh keeps the old copy. Budget: 8 runs x 6 fetches = 48 subrequests and <= 48 KV writes per day; pipeline runs add ~16 relay requests each (6 feeds + <= 10 pages) = ~64 requests and <= 40 page writes per day on 4 scheduled runs; totals are two orders of magnitude under the free limits (100k requests, 1k KV writes). Workers Free allows 5 cron triggers per account; this uses one.
- **D8 Pipeline module `src/relay.js` + `runSource` swap.** `resolveRelay(env, logger)` -> `{ url, token }` when `RELAY_URL` and `RELAY_TOKEN` are both non-blank after `trim()` (trailing slashes stripped from the URL), `null` when either is blank; when both are present but `RELAY_URL` is not an `https:` URL or carries credentials/query/hash, log one `logger.warn('relay disabled: RELAY_URL must be an https URL without credentials, query or fragment')` and return `null` (degrade like the LLM layer, never abort the run). `relayFeedUrl(relay, id)` = `${relay.url}/feed/${encodeURIComponent(id)}`; `relayPageUrl(relay, id, pageUrl)` = `${relay.url}/page/${encodeURIComponent(id)}?u=${encodeURIComponent(pageUrl)}`. `createRelayFetch({ source, relay, direct, logger, state })` returns a `fetchText(url, opts)` that routes `url === source.url` to the feed route and every other URL (sitemap pages) to the page route with `timeoutMs = Math.min(opts.timeoutMs ?? RELAY_TIMEOUT_MS, RELAY_TIMEOUT_MS)` (`RELAY_TIMEOUT_MS = 15_000`; pages keep their 8 s), returns `{ ...res, finalUrl: url }` (so `runSource` never emits a `redirected to <relay url>` note), records the primary request's outcome in `state.primary` (`{ via: 'relay', stale? }` or `{ via: 'direct', failure: errorClass(err) }`), and on ANY thrown error (`HttpError` 401/404/429/5xx, `TimeoutError`, network, `BodyTooLarge`) logs `logger.warn(\`${source.id}: relay failed (${class}) for ${feed|page}; falling back to direct${detail ? ` [${detail}]` : ''}\`)` and returns `direct(url, opts)`. `relayNote(state)`: `via relay` | `via relay (stale <value>)` (value = `x-relay-stale` header trimmed and limited to 40 printable ASCII chars; `via relay (stale)` if nothing printable remains) | `relay: <class>, fell back to direct`. Only the primary (feed/sitemap) request shapes the note; page-level relay failures are logged and fall back per page (the slug fallback in `parseSitemap` already covers a page that also fails directly). In `runSource`: `const relay = deps.relay && source.viaRelay === true ? deps.relay : null;`, `fetchText = relay ? createRelayFetch(...) : direct`, and after the race `const note = relayNote(state); if (note) result.note = result.note ? \`${result.note}; ${note}\` : note;` placed after the `apiNote` line (youtube sources never use the relay, so they never meet). `run()` computes `const relay = resolveRelay(env, logger)` once, passes it to `createHttpClient({ ..., relay })` and into the `runSource` deps; `scripts/probe-sources.mjs` does the same from `process.env`. `once()` adds `headers: res.headers` to its result so the wrapper can read `x-relay-stale`.
- **D9 http.js relay-host rules.** `createHttpClient({ ..., relay = null })` derives `relayHost = new URL(relay.url).hostname`. `headersFor`: when `host === relayHost` send the identifying `userAgent` (Ahead UA) and `x-relay-token: relay.token`; because headers are recomputed per redirect hop, a hop to another host drops the token (same mechanism the GitHub token relies on). `retryable()`: `host === relayHost` -> `false` with the comment that the Worker already retries upstream and serves stale copies, and that the direct fallback must still fit the 45 s backstop (15 s relay attempt + 20 s direct attempt + no second direct attempt since < 25 s remain). Redaction: a client-scoped `scrub(text)` replaces every occurrence of the token value with `REDACTED` and is applied to the URL and to every `detail` value (including the body snippet) before `HttpError`/`TimeoutError`/`BodyTooLarge` are constructed in `once()`/`readBody`; `headerDetail` skips `authorization` and `x-relay-token` even if `DETAIL_HEADERS` is ever extended. Together with `errorSummary`/`errorClass` (no URLs) this keeps the token out of `error`, `detail`, `note`, logs and `meta.json`.
- **D10 Token handling (ops).** 32 random bytes as 64 hex chars from Node `crypto.randomBytes(32).toString('hex')`, written by the generating `node -e` straight to `%LOCALAPPDATA%\ahead\relay-token.txt` (outside the repo; this local copy is what later steps and the user use for `node scripts/fetch.mjs` with the relay and for rotation). Set with `Get-Content -Raw <file> | npx wrangler secret put RELAY_TOKEN` (cwd `relay/`) and `Get-Content -Raw <file> | gh secret set RELAY_TOKEN --repo Sudish007/ahead`; `gh secret set RELAY_URL --repo Sudish007/ahead --body <workers.dev url>`. PowerShell appends a newline when piping to native programs, which is why both the Worker and the pipeline `trim()` the token before comparing/sending (an untrimmed `\n` would also make Node reject the header value). The token value never appears in a command line, a repo file, a FEAT `findings` field, a commit message, a log or a report: report only "set" and the length (64). Pre-commit check: `git diff --cached | Select-String -Pattern '[0-9a-f]{64}'` must return nothing.
- **D11 Worker configuration.** `relay/wrangler.toml`: `name = "ahead-relay"`, `main = "src/index.js"`, `compatibility_date = "2026-10-01"` (what the probe used on wrangler 4.151.2), `workers_dev = true`, `[observability] enabled = true`, `[triggers] crons = ["0 */3 * * *"]`, `[[kv_namespaces]] binding = "RELAY_CACHE" id = "<from wrangler kv namespace create RELAY_CACHE>"`. Secrets are never in the toml.
- **D12 The Worker is unit-tested in Node.** `relay/src/index.js` exports `createRelay({ fetchImpl, now, sleep, log } = {})` -> `{ fetch(request, env, ctx), scheduled(controller, env, ctx) }` plus the constants (`FRESH_MS`, `MAX_STORE_BYTES`, `UPSTREAM_TIMEOUT_MS`, `RETRY_429_MS`, `STORE_TTL_S`, `CRON_GAP_MS`), and `export default createRelay()` (globals resolved at call time). Adding a dynamic host to `PACING` would slow `thebatch` page fetches for no measured gain.
