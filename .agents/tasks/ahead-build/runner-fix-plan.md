## Decisions (settled)

- **D1 Diagnostic detail lives in a new `detail` field, not in `error`.** `error` stays the short class (`HTTP 403`) because the schema caps it at 120 chars and the UI prints it. `detail` (string, <= 400 chars, single line) is written to `data/meta.json` for failed sources, appended to the `runSource` warn line (so it appears in the Actions log), and printed under the CLI table. It stays after the fix; it is bounded and costs nothing.
- **D2 Browser headers by default, two identified-host exceptions.** `BROWSER_USER_AGENT = Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/155.0.0.0 Safari/537.36` (Chrome stable 155, October 2026). `www.reddit.com` and `api.github.com` keep the `Ahead/<version>` UA: Reddit's API rules penalize browser-UA spoofing and Reddit currently works from the runner; GitHub asks clients to identify themselves. `Accept-Language: en-US,en;q=0.9` on every request. `ACCEPT.feed` becomes exactly `application/rss+xml, application/atom+xml, application/xml;q=0.9, text/html;q=0.8, */*;q=0.7`. `ACCEPT.html` stays `text/html` (sitemap page fetches; `tests/sitemap.test.js` pins it). Redirects keep being followed by the existing manual loop (5 hops).
- **D3 YouTube policy: 3 attempts with 2 s / 8 s backoff, 404/5xx/429/network all retryable, `Accept: */*`.** Local counts favour no feed Accept (24/24 vs 19/24 and 17/24); the runner probe in FEAT-001 decides: use the header variant with the most 200s across the six channels; on a tie use `*/*`. Keep the `channel_id=` URL: the bare host only redirects, the `UU` playlist form was worse locally. Add `cookie: CONSENT=YES+cb; SOCS=CAI` for `www.youtube.com` **only if** the FEAT-001 run shows a YouTube `location` header pointing at `consent.youtube.com`; otherwise no cookie. Switch `yt()` to `playlist_id=UU…` **only if** the probe shows the UU form succeeding on at least two channels where `channel_id` got zero 200s.
- **D4 arXiv fallback: 15 s timeout so the existing single retry fits the 45 s backstop.** `fetchApi` passes `timeoutMs: 15_000`; worst case RSS 0.5 s + 15 s + 2 s sleep + 15 s = 32.5 s < 45 s, and 27 s remain at the retry check (>= 25 s). The `empty` + fallback-failed note becomes `api fallback failed (<class>)`. Status stays `empty` (valid empty RSS is not a fetch failure; the health button must not go red on a slow arXiv API). Not a parser/filter bug, so no new fixture; unit tests cover the timeout option and note text.
- **D5 Still-blocked sources stay in the registry and stay `failed`** with a short specific string from a new `errorSummary(err, { onRunner })`: `blocked from GitHub runner: 403 Cloudflare` (when `env.GITHUB_ACTIONS === 'true'` and the response `server` header is cloudflare), `blocked: 403 Cloudflare` elsewhere, `HTTP 404 (3 attempts)` when more than one attempt was made, otherwise the existing `errorClass`. No proxies, mirrors, scrapers or keys. UI semantics unchanged (the health button still counts them).
- **D6 Runner probe is a workflow_dispatch input, not a separate workflow.** `scripts/probe-runner.mjs` prints a status/header/snippet matrix for the 7 blocked hosts and the 6 YouTube channels under several header variants; `refresh.yml` gets `inputs.probe` (boolean, default false) and a `continue-on-error` step that runs it before the fetch. Dispatch with `gh workflow run refresh.yml -f probe=true`. A plain push still produces the normal run (with `detail` strings in meta.json).
