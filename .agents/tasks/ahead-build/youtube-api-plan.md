## Decisions (settled; do not re-open)

- **D1 One new module `src/parsers/youtube.js` owns the API request and mapping; `runSource` owns the branch and the fallback.** `runSource` tries `fetchYoutubeApi(source, ctx)` when `source.type === 'youtube'` and a non-blank key is present, and on ANY throw records `apiNote = 'api: <errorClass(err)>, fell back to feed'`, logs a warn, and continues into today's generic `fetchText(source.url)` + `parseFeed` path unchanged. The note is attached in `runSource` after the try/catch so it is present both when the feed path succeeds (`status ok/empty`, `note`) and when it fails too (`status failed`, today's exact `error`/`httpStatus`/`detail`, plus `note`). A failing API therefore can only add a note, never change status or error.
- **D2 Request.** `GET https://www.googleapis.com/youtube/v3/playlistItems?part=snippet,contentDetails&maxResults=15&playlistId=<UU…>&key=<encodeURIComponent(key)>`, built with a template literal exactly in that parameter order (the comma in `snippet,contentDetails` stays literal; tests compare the full string). `<UU…>` = the `channel_id` query parameter of `source.url` with the leading `UC` replaced by `UU`; the id is parsed with `new URL(source.url).searchParams.get('channel_id')` and must match `/^UC[A-Za-z0-9_-]+$/`, otherwise the API path throws `ParseError('no channel_id in url')` and the feed path runs. `accept: ACCEPT.json`, `timeoutMs: 8_000`, one request per channel per run, no pagination.
- **D3 No retry for `www.googleapis.com` (`retryable()` returns false, like `www.reddit.com`).** Budget math inside the 45 s backstop: worst case the API consumes 8 s (timeout), leaving 37 s; the feed fallback's three fast-failing attempts need ~10.5 s and still have >= 25 s left at both retry checks (36.9 s, then 26.8 s after the 8 s backoff). With the default 20 s timeout or any retry the third feed attempt would be skipped, which would make a source worse than today.
- **D4 Mapping (feed-shaped record, same fields `parseFeed` emits).** `title = cleanText(snippet.title)`; `url = https://www.youtube.com/watch?v=<videoId>` with `videoId = contentDetails.videoId ?? snippet.resourceId.videoId` matching `/^[A-Za-z0-9_-]+$/`; `publishedAt = parseDate(contentDetails.videoPublishedAt ?? snippet.publishedAt, ctx.now)`; `summaryText = cleanText(snippet.description)`, cut with `stripSponsors()` when `source.category === 'media'` (mirrors `summaryFields`; true for all six sources), and `bodyLength = summaryText.length`, both only when non-empty; `authors = [cleanText(snippet.channelTitle)]` when non-empty; no `signals` (playlistItems carries no view counts; a second `videos?part=statistics` request would break the one-request rule), no thumbnail, no `extra`, no `enclosureType`. Records without a title or video id, and placeholder titles `Private video` / `Deleted video`, are dropped (counted in `fetched`, not `kept`). `nativeIndex` = array index. `applySelection(out, source, ctx, fetched)` applies `maxAgeDays`/`maxItems` exactly as the feed path. The success result is `{ ...selection, httpStatus: res.status, note: 'api' }` and NEVER sets `finalUrl` or `requestedUrl` (`res.finalUrl` carries the key; leaving both unset also skips `runSource`'s redirect note). Source ids are untouched so `items[].sources[].id` and the browser's localStorage state survive.
- **D5 Redaction lives in `src/http.js` as `export function redactKey(text)`**: `String(text).replace(/(googleapis\.com\/[^\s"'<>]*?[?&]key=)[^&\s"'<>]*/gi, '$1REDACTED')`. It rewrites `key=<value>` only inside a googleapis.com URL, anywhere in a string (verified during planning: the full playlistItems URL, `?key=` as first parameter, two URLs in one string; `https://example.test/feed?key=abc` is untouched). Applied in the `HttpError` constructor (`this.url = redactKey(url)`, message uses the redacted URL, every string value of `detail` is redacted), in `TimeoutError` and `BodyTooLarge` messages, in `formatDetail` on every value, and on the `redirected to …` note in `runSource`. `errorClass`/`errorSummary` return no URLs and are unchanged.
- **D6 Key threading mirrors `githubToken`.** `run()` computes `youtubeApiKey = typeof env?.YOUTUBE_API_KEY === 'string' ? env.YOUTUBE_API_KEY : ''` and passes it in the `runSource` deps; `runSource` normalises `typeof deps.youtubeApiKey === 'string' ? deps.youtubeApiKey.trim() : ''` into `ctx.youtubeApiKey`, so an empty or whitespace secret (`${{ secrets.YOUTUBE_API_KEY }}` renders `''` when unset) behaves exactly like an absent one. `scripts/probe-sources.mjs` passes `process.env.YOUTUBE_API_KEY ?? ''` so `npm run probe` mirrors the pipeline. `scripts/probe-runner.mjs` is not touched (feed URLs only, no key).
- **D7 ytViews trade-off is documented, not patched.** API-fetched items have no `ytViews`, so the `N views` why-clause and the `0.15*log2(1+ytViews)` term apply only to feed-fetched items; stored counts from earlier feed runs are kept by `mergeSignals`. `src/score.js`, `src/brief.js`, `app.js`, `index.html`, `styles.css`, `sources.config.mjs` are not modified.
- **D8 Test hygiene.** `tests/cli.test.js` adds `YOUTUBE_API_KEY: ''` to the spawn env next to `LLM_API_KEY: ''` so a developer's shell key cannot reach the CLI tests. Every test that sets a key provides an `overrides` entry for the exact API URL (`fixtureFetch` throws on unmapped URLs; that error message would contain the key). The new fixture is synthesized from `tests/fixtures/youtube-gpumode.xml` (same six videos) so the API path and the feed path can be asserted item-for-item equal.
